# Data and Output Layout

Local inputs and generated products are excluded from Git. Preserve original CASALS and 3DEP source files; workflow runs write beneath `outputs/`.

| Path | Contents | Handling |
| --- | --- | --- |
| `data/raw/casals_l1b/` | Original CASALS L1B H5 granules | Read-only source inputs. |
| `data/raw/tdms/` | TDMS recordings, index sidecars, viewer assets, and notes | Source/reference material. |
| `data/reference/3dep/` | 3DEP LAS/LAZ clips | External reference data with source metadata. |
| `data/derived/` | Products intentionally reused as inputs | Record the source workflow before reuse. |
| `outputs/refh/<h5-stem>/` | Refh export, filtering, DSM, ground, classification, and evaluation products | Regenerable, per-input workflow outputs. |
| `outputs/peaks/<h5-stem>/` | Component, pulse, sweep, candidate-position, and validation products | Regenerable waveform analyses; secondary peaks are not official returns. |
| `outputs/reference/<h5-stem>/` | 3DEP download, diagnosis, and transfer outputs | Comparison products; transferred labels remain pseudo-reference. |
| `outputs/notebooks/` | Products generated by current real-data notebooks | Local notebook outputs; inputs and parameters are recorded in each notebook. |
| `outputs/baseline_pre_refactor/` | Historical outputs retained for comparison | Do not describe these as newly generated results. |
| `config/local/` | Workstation-specific GUI settings | Ignored by Git; do not publish. |

The source inventory records the original local H5, TDMS, reference, and baseline-output counts in [refactor_baseline.md](refactor_baseline.md). Original input data and all earlier notebooks remain preserved: 21 archived research notebooks plus four superseded root demos under `research/archived_notebooks/`. Exactly four current notebooks are under `notebooks/`; `.compile_tmp/` is an ignored local scratch directory used for execution and visual checks.

The `outputs/` and local data trees are untracked. Remove historical products only after their provenance and required comparisons are recorded. The current notebook outputs are explained in [refactor_improvement_report.md](refactor_improvement_report.md).
